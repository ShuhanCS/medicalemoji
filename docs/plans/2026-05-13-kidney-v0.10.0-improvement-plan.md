## Top Priority Changes

### 1. Finish Required Frequency Evidence

This is the biggest blocker. Unicode requires screenshots for:

- Google Search.
- Google Video Search.
- Google Trends Web Search with `elephant`.
- Google Trends Image Search with `elephant`.
- Google Books Ngram Viewer with `elephant`.

Current state:

- Trends Image is acceptable draft evidence.
- Books Ngram is acceptable draft evidence.
- Trends Web is partial and must be recaptured.
- Google Search and Google Video Search are missing because automated capture hit CAPTCHA.

Next packet target:

- Replace the partial Trends Web screenshot with a working chart.
- Add clean Google Search and Google Video screenshots with visible result counts.
- Put all five screenshots directly in the proposal PDF source.
- Keep screenshot metadata: query, URL, date, region/language if visible.

### 2. Make The Visual Paradigm Section Stronger

Successful proposals treat the image as a simple paradigm, not an exact vendor drawing. The current kidney proposal has images and a visual review board, but the written argument should be sharper.

Next packet target:

- Add a short "Essential visual cues" subsection:
  - paired organ form,
  - medial indentation,
  - vessels/ureters,
  - not a food bean,
  - not a generic red organ.
- Add a short "Vendor variation allowed" subsection:
  - color may vary,
  - vendors may simplify vessels,
  - vendors may use a pair or simplified anatomical rendering,
  - exact Medical Emoji art is not required.
- Keep the 18x18 comparison board in the proposal, not only as a reference file.

### 3. Strengthen The Replacement Analysis

The proposal should explain what users currently have to use and why each substitute fails.

Next packet target:

Add a table under `Already Represented` or `Breaks New Ground`:

| Existing emoji/sequence | Why it is insufficient |
| --- | --- |
| Bean | Food meaning; wrong tone for clinical, donor, transplant, and anatomy communication. |
| Drop | Can mean water, sweat, tears, blood, or urine; does not identify kidney. |
| Hospital | Institution, not organ/function. |
| Pill | Treatment/medication, not kidney anatomy or kidney function. |
| Syringe | Procedure or injection, not kidney. |
| Anatomical heart/lungs/brain | Different organs and meanings. |

### 4. Tighten Broad-Building-Block Framing

The current `v0.9.0` packet improved this by adding kidney beans, kidney-shaped objects, hydration, filtration, and everyday contexts. The next version should make this even cleaner.

Next packet target:

- Lead with everyday/body-language use before disease burden.
- Keep public-health sources as support, not the main argument.
- Avoid sounding like a nephrology advocacy campaign.
- Keep kidney bean as a "language and shape familiarity" bridge, not as a claim that this emoji replaces bean.

### 5. Move Support Letters To A True Appendix Role

The support-letter links should remain in the proposal source, but the narrative should make clear they are coalition context, not usage-frequency proof.

Next packet target:

- Add a short sentence before the letter list:
  "These letters demonstrate expert and patient-advocacy support, but the expected-usage case relies on the required frequency evidence above."
- Consider moving the full support-letter list to an appendix after all Unicode criteria are complete.

### 6. Remove Internal Packet Language From The Final PDF Source

The final public PDF should not feel like a GitHub packet. Internal notes are useful in manifests and checklists, but the proposal source should read cleanly.

Next packet target:

- Keep `SUBMIT` filename for version control, but remove wording like "packet", "reference-only", "draft evidence", and "current packet" from the final PDF source wherever possible.
- Replace with reviewer-facing language:
  - "Figure 1"
  - "Frequency evidence"
  - "Appendix"
  - "Source links"
- Keep blockers in the manifest and finalization checklist until resolved.

## Practical Definition Of Done

The next version is meaningfully improved when:

- The proposal source includes all five required frequency screenshots.
- The visual distinctiveness section explains essential cues and vendor variation.
- The "already represented" objection has a concrete substitute-failure table.
- Support letters are clearly appendix context.
- Internal packet language is removed from the PDF-facing source.
- Remaining blockers are only eligibility/TKF coordination, final signoff, and public PDF hosting.
