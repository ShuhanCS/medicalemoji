# Kidney v2.7.0 Space-Efficiency Plan

## Goal

Create a shorter, easier-to-review Kidney proposal PDF without deleting any proposal argument, required field,
example artwork, or frequency exhibit.

## Audience

The PDF is written for Unicode emoji reviewers applying the live 2026 proposal format. Reviewers need legible,
traceable evidence; they do not need one frequency exhibit per page.

## Format Decision

The Unicode proposal guidance requires the first-page identification material, example images, selection-factor
answers, and five frequency screenshots. It does not require each screenshot to begin on a separate page. The
large blank areas in v2.6.0 came from repository CSS that forced four evidence headings onto new pages.

For v2.7.0:

1. Preserve the complete proposal text and all nine embedded images.
2. Crop only the unused lower portion of the Search and Video screenshots. Keep the query, search type, Tools
   menu, visible count, and enough result context in each image.
3. Let Search use the otherwise empty lower portion of the Expected usage page.
4. Let Video and Google Trends Web Search share the following page, then place Image Search and Books Ngram
   together on the next page at readable widths.
5. Keep headings with their descriptions and images and prevent evidence blocks from splitting awkwardly.
6. Accept seven or eight pages based on rendered legibility; do not force a lower count by shrinking evidence
   beyond comfortable review size.

- `submissions/v2.7.0/` as the immutable next review packet.
